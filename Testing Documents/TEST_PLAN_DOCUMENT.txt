                        4. LỊCH TRÌNH KIỂM THỬ
================================================================================

4.1. Timeline tổng thể (4 tuần)

    TUẦN 1: UNIT TESTING & PREPARATION (5 ngày)
    ------------------------------------------------
    Ngày 1-2:   Chuẩn bị môi trường test
                Cài đặt công cụ (Jest, Supertest, Postman)
                Setup test database
    
    Ngày 3-4:   Viết Unit Tests
                - Cart calculation logic
                - Order price calculation
                - Coupon discount logic
                - User authentication
    
    Ngày 5:     Review & chạy Unit Tests
                Fix bugs phát hiện từ Unit Test

    TUẦN 2: INTEGRATION TESTING (5 ngày)
    ------------------------------------------------
    Ngày 6-7:   API Integration Testing
                - Test tất cả API endpoints
                - Test database connections
                - Test API response format
    
    Ngày 8-9:   Component Integration
                - Frontend-Backend integration
                - MoMo payment integration
                - Email notification
    
    Ngày 10:    Review & fix bugs

    TUẦN 3: SYSTEM & E2E TESTING (5 ngày)
    ------------------------------------------------
    Ngày 11-12: System Testing
                - Test toàn bộ luồng User
                - Test toàn bộ luồng Admin
    
    Ngày 13-14: End-to-End Testing (Cypress)
                - User journey: Browse -> Add to cart -> Checkout
                - Admin journey: Login -> Manage products -> Update orders
    
    Ngày 15:    Cross-browser testing (Chrome, Firefox, Edge)

    TUẦN 4: SECURITY, PERFORMANCE & UAT (6 ngày)
    ------------------------------------------------
    Ngày 16-17: Security Testing
                - SQL Injection
                - XSS attacks
                - CSRF protection
                - Authentication/Authorization
    
    Ngày 18-19: Performance Testing
                - Load testing (100, 500, 1000 users)
                - Stress testing
                - API response time
    
    Ngày 20-21: UAT (User Acceptance Testing)
                - Product Owner testing
                - Stakeholder demo
                - Final bug fixes

4.2. Milestone

    Milestone                   Ngày dự kiến        Deliverable
    ---------                   ------------        -----------
    M1: Unit Test hoàn thành    Ngày 5              Unit Test Report
    M2: Integration Test done   Ngày 10             Integration Test Report
    M3: System Test done        Ngày 15             System Test Report
    M4: Security Test done      Ngày 17             Security Test Report
    M5: Performance Test done   Ngày 19             Performance Test Report
    M6: UAT & Go-live           Ngày 21             Final Test Report

                        5. RỦI RO VÀ BIỆN PHÁP
================================================================================

5.1. Rủi ro tiềm ẩn

    STT     Rủi ro                          Mức độ      Biện pháp phòng ngừa
    ---     ------                          ------      --------------------
    1       Thiếu test data                 CAO         Chuẩn bị seed data trước
    2       Môi trường test không ổn định   TRUNG       Backup môi trường, có plan B
    3       API thay đổi đột ngột           TRUNG       Version control, changelog rõ ràng
    4       Thiếu nhân lực test             CAO         Cross-training, backup tester
    5       Phát hiện bug critical muộn     CAO         Smoke test mỗi build
    6       MoMo sandbox không hoạt động    TRUNG       Mock payment, fallback COD
    7       Database bị corrupt             TRUNG       Backup DB hàng ngày

5.2. Kế hoạch dự phòng

    Tình huống                              Giải pháp
    ----------                              ---------
    Test bị delay 2 ngày                    Tăng người test, giảm test cases ưu tiên thấp
    Môi trường production không sẵn sàng    Test trên staging, delay go-live
    Critical bug phát hiện ngày cuối        Hotfix team riêng, delay UAT 1-2 ngày
    Tester bị nghỉ đột xuất                 Backup tester thay thế, chia lại task

7.1. Metrics theo dõi

    Metric                      Target              Critical Level
    ------                      ------              --------------
    Test Cases Passed           ≥ 95%               < 90%
    Test Coverage (Code)        ≥ 80%               < 70%
    Critical Bugs               0                   > 0
    High Bugs                   ≤ 5                 > 10
    API Response Time           < 500ms             > 2s
    Page Load Time              < 3s                > 5s
    Test Execution Rate         100%                < 95%

7.2. Định nghĩa mức độ bug

    Severity        Mô tả                                       Ví dụ
    --------        -----                                       -----
    CRITICAL        Hệ thống crash, mất dữ liệu                 Database corrupt, payment failed
    HIGH            Chức năng chính không hoạt động             Login failed, cannot add to cart
    MEDIUM          Chức năng phụ lỗi, có workaround            Search không chính xác
    LOW             Lỗi UI/UX, không ảnh hưởng chức năng        Button màu sai, typo

7.3. Bug lifecycle

    Status              Mô tả                           Người xử lý
    ------              -----                           -----------
    NEW                 Bug mới được tạo                QA
    ASSIGNED            Đã assign cho dev               Dev
    IN PROGRESS         Dev đang fix                    Dev
    FIXED               Dev đã fix                      Dev
    READY TO TEST       Sẵn sàng retest                 QA
    VERIFIED            QA verify fix thành công        QA
    CLOSED              Bug đã closed                   QA
    REOPENED            Bug vẫn còn sau khi fix         QA
